# P5.2 — core sender screens: blocked

**Status:** not started. Blocked on a missing dependency, not on effort.

## Why

Build guide P5.2 says, in its first line:

> Build against the design system (`docs/design-system.md`, tokens in
> `design-system-visual.html`).

Neither file was supplied to this build (see `docs/COMPANION-DOCS.md`). Screens built
against an invented visual language would be thrown away when the real one arrives, and
worse, they would set expectations in review about a design nobody approved.

## What was built instead

Everything those screens will call, with tests:

| P5.2 screen | Backing surface | Where |
|---|---|---|
| Onboarding | phone verification, sessions, assurance levels | `src/iwp/app/auth.py` |
| Plan creation | plan versions, categories, recurring rules | `src/iwp/domain/plans.py` |
| Request inbox and approval | request state machine, tier classification, step-up | `src/iwp/domain/requests.py`, `src/iwp/app/auth.py` |
| Transaction history | requests and transactions with intent and settlement state separate | `src/iwp/domain/requests.py` |
| Detail view | receipts, disclosures, delivery audit, cancellation window | `src/iwp/app/disclosures.py`, `src/iwp/channels/gateway.py` |

## Acceptance criteria that are already satisfiable

Two of P5.2's criteria are not visual and are already true:

- **"Approval is one action from a push notification without opening the app."** The
  approval path takes an assurance level and a channel and does not care which surface
  supplied them; `tests/test_channels.py` approves from a WhatsApp button and an SMS
  keyword, and a notification action is the same call.
- **"Failed transactions display with a plain-language explanation."** The explanation
  exists on the transaction (`failure_reason`) and in copy
  (`settlement.failed`), which says the money came back and nothing was lost.

Three are genuinely visual and wait for the design system: history being list-only with
no charts, empty states being warm and actionable, and full bilingual presentation. The
copy is already bilingual (`src/iwp/channels/copy.py`); its presentation is not.

## What is needed to unblock

`docs/design-system.md` and `design-system-visual.html`. The §6.2 banned-word list in
the same document is also needed to complete the P7.2 eval gate — see
`docs/open-questions.md` item 6.
